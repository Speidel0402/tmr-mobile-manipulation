# 实机故障与修复记录

## 底盘

- **转角超过 90°**：阶段间重复累计旋转。当前由单次里程计闭环定义顺时针目标，门框横移不会重复计入转角。
- **穿门横移过量并碰右门框**：曾把错误缺口和错误侧向符号作为目标。当前门框由本轮地图候选与双雷达多帧共同确认，目标冻结为两门边中点，并以完整车体外廓计算扫掠。
- **过门后持续前进**：旧流程依赖桌腿识别来决定停止，识别不到就继续搜索。当前主流程改为门前 `0.50 m` + 固定前进 `1.20 m`，到达后无条件锁存零速。
- **碰撞误报**：底盘、线缆、机械臂回波和 SLAM 残影落入旧固定阈值。当前剔除实测车体内部回波，按运动方向和制动距离检查实时雷达；地图需形成占用簇才作为二级证据。
- **命令抢占/离线**：旧脚本、Nav2、遥控和任务可能同时发布速度。当前使用 `mission_control_lease.py` 与 `cmd_vel_adapter.py` 独占控制器输入，异常后锁存零速。

## 抓取

- **夹爪先闭合再下降**：动作被拆成远程零散命令，时序互相越过。当前完整脚本固定为 `open -> align -> descend -> close -> lift`。
- **顶层轻微回弹/旧阈值拒绝继续**：控制器交接会带来小幅姿态变化。当前优先恢复实机成功的固定关节目标，再以关节误差、FK 高度和方向验证。
- **接近关节目标时卡住**：PTP 服务在 `0.002 rad` 附近可能长期保持 RUNNING。当前首轮采用 `0.006 rad` 动作容差和硬超时；若实测终点仍松，只进行一次 `0.0025 rad`、18 秒上限的精确收敛，不会无限等待。
- **下降少约 9 mm**：仅放宽动作容差会让短距离终点提前成功。当前每次 PTP 后读取实际关节终点，下降层还用 FK 检查地面坐标高度，残差只做一次有界修正。
- **已夹到杯子却被判失败并重新张开**：旧逻辑要求夹爪位置至少达到绝对 `0.20`，实机杯子使其停在 `0.178–0.196`。当前用相对闭合行程、stall、动作状态和目标间隙综合判断；空夹完全闭合仍不会被误判为抓取。
- **相机服务因深度图停止**：深度流掉线会使旧快照接口整体失败。当前 RGB 是唯一必需数据，深度和内参可选；杯沿校准不依赖深度图。
- **MoveIt 服务缺失**：视觉伺服需要 FK 和 Cartesian Path，但完整 MoveIt 执行并非必要。`start_left_ik_service.py` 只启动左臂求解服务，并禁用轨迹执行。
- **PTP 结束后状态话题消失**：动作服务器清理与阻抗控制恢复存在竞争，可能使硬件掉到 UNCONFIGURED。当前先等待 PTP 清理，再恢复硬件生命周期、两个状态发布器与阻抗控制；若 FCI 返回网络异常，重启 `franka_fr3_arm_controllers` 进程，而不是反复发送运动目标。

## 比赛部署原则

实时控制和感知服务应预先部署并常驻机器人本机；SSH/Codex 只发送低频的“开始/停止/状态”请求。每个动作都有明确的完成条件和超时，异常后保持当前夹爪状态并让底盘锁存零速，避免远程连接抖动造成长时间停顿或乱序动作。

## 综合流程

- **失败后从头重跑导致重复转向/前进**：综合协调器持久化阶段检查点。底盘成功后写入 `BASE_LOCKED_AT_PICKUP`；抓取失败只能用 `--resume-grasp` 恢复，明确跳过全部底盘动作。
- **底盘与机械臂 ROS 版本/Domain 混用**：综合脚本运行在机械臂主机，但底盘任务通过一次 SSH 在 `.50` 本地 Domain 97 中执行；抓取在 `.100` 本地执行，不桥接实时速度、图像或关节流。
- **抓取动作已结束但控制器随后掉线**：`success` 不再是综合任务终点。必须等 PTP 完全清理、硬件生命周期和阻抗保持稳定，并收到 `cycle_complete`，综合任务才进入 `COMPLETE`。
- **阶段异常后旧速度恢复**：门口流程结束或任何异常后，底盘任务租约保持锁存，适配器持续输出零；综合任务不会自动释放给 Nav2、旧脚本或遥控。
